# 会话模型与思考设置

模型选择优先使用会话的 `selectedModel`，缺失时使用 `settings.selectedModel`。
桌面端通过 `selectedModelJson` 写入会话历史；Web 的本地选择覆盖先保存在会话映射，发送后由桌面宿主落入历史。
选择模型仍会更新全局默认，供未配置模型的会话使用。

思考开关与档位通过 `chatRuntimeControls.thinkingByConversation[conversationId]` 保存。
会话第一次调整控件时复制原有思考默认值，此后的调整仅修改该会话。
每个会话内继续按供应商类型/请求格式和模型 ID 记忆档位；同一模型在不同会话中可选不同档位。
尚无独立设置的会话继承原有 `reasoningByModel`、`reasoningByProvider` 和全局默认值，默认档位为 `high`。
联网与 Plan mode 保持原有全局设置语义。

可选档位由 `resolveModelThinking` 根据供应商类型及模型 ID 解析：优先使用内置模型目录的 thinking 数据，缺失时读取运行期模型数据，最后使用代码兜底规则。
读取时将档位限制在模型支持的范围内，不回写存储；显式调整时按目标模型校验后保存。

桌面主界面、分屏、发送、排队和手动压缩均按目标会话解析思考设置。
入队时保存目标会话的快照，后续调整不会改变已排队消息的档位。
Web 在草稿绑定正式会话 ID 时迁移思考设置；发往网关的请求仅携带目标会话的运行参数。
思考设置使用现有设置持久化与网关同步通道，不增加历史数据库字段，因此独立导出会话历史不会包含这些设置。


跨端同步按会话合并，`thinkingByConversationRevisions` 为每个会话保存递增的 `version` 和客户端 `writerId`。
比较顺序为 `(version, writerId)`，同会话并发修改确定性收敛，不同会话互不覆盖；旧版无版本记录不能覆盖已有版本的记录。
桌面、Web 与网关缓存均使用此规则；网关缓存合并在锁内完成，旧快照也会收到合并后的广播。
草稿迁移和删除会话时删除思考快照，保留删除版本，防止在途旧快照恢复已删除记录。删除版本暂不回收，未来回收需有同步确认机制。
分支会话复制源会话当时的有效思考设置（包括继承的默认值），后续各自独立修改。
请求解析只读取目标会话，不遍历全部历史记录，也不携带版本元数据。
