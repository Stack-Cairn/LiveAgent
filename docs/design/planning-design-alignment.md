# Planning 对齐主线 UI 规范

分析基线：2026-09-27 更新后的 `origin/main`，提交 `341b005d`。Planning 在
`feat/planning-calendar-main` 上迁入；本文记录主线已有的规则、对应源码和计划页的落地方式。

## 规范的依据与优先级

1. UI 重构期间的样式变量约定（字号、颜色、组件复用规则）；下文已摘录日历需要遵守的部分。
2. UI 颜色迁移记录中的颜色变量类型和迁移边界，同样摘录在「颜色与主题」一节。
3. `crates/agent-ui/src/components/ui/`、`components/settings/` 和共享样式是运行中的实现依据。
4. UI 设计审计是历史问题与改进记录，不是要求每个新页面复制的固定视觉模板。

主线的实现仍保留历史特例。不能把某个旧页面中的固定字号、色值或手写按钮当作新页面的规范，
也不能为了统一，把时间轴等专用交互硬套成普通表单组件。

## 从主线归纳的设计体系

### 页面框架与信息层级

`application/ApplicationView.tsx` 负责共享页面入口；`application/AppWorkbenchChrome.tsx`
负责常驻顶栏、侧栏开关和宿主窗口行为。业务页不再独立绘制这些窗口控件。

`components/hub/HubChrome.tsx` 的 `HubHeader` 提供页面标题、说明和右侧动作：

- 常规标题 `text-xl`；突出标题 `text-3xl`，字重 `font-semibold`，紧凑字距。
- 说明使用 `text-sm` 或 `text-xs`、`text-muted-foreground`。
- 页面横向留白从 `px-5`，依次到 `sm:px-6 / lg:px-8 / xl:px-10`。
- 标题内部最大宽度为 `1320px`。内容宽度应服从页面用途，日历可使用可用空间铺开。
- 全局导航、页面动作、局部筛选分别占据清晰层级；不重复增加第二套导航壳。

这是结构与层级约定，不表示每个 Hub 都要使用彩色光晕、玻璃卡片或相同装饰背景。
计划页属于高信息密度工具，使用中性的背景、细边框与低对比辅助面板。

### 字体、尺寸与区域缩放

样式入口为 `styles/base.css`，统一加载 `tokens.css`、`animations.css`。
Tailwind v4 在 CSS 中用 `@theme` 声明，不建立额外 `tailwind.config.js`。

- 普通文字采用标准 rem 档位：正文 `text-sm`，次要说明 `text-xs`，标题按层级选用更大档位。
- `text-tiny` 仅用于紧凑计数、徽标或键帽；不用于普通说明文字。
- 不恢复 `11px / 13px / 14.5px` 等零散字号。局部 CSS 可用 `var(--text-xs)` 等同源变量。
- 间距优先用 Tailwind 标准尺度（基准 `--spacing: 0.25rem`）；等宽高使用 `size-*`。
- 页面继承 `--zone-font-scale`；Dialog 使用共享的 0.9 区域档位。
- Select、Popover 等通过 React context 把字号档位传到 portal，避免菜单脱离对话框缩放。

日历的分钟转像素、列宽、拖动位置属于运行时几何；这些像素不等同于写死普通界面字号。

### 颜色与主题

背景、正文、辅助文字、边线、主操作分别用 `background / foreground / muted-foreground /
border / primary` 等语义角色。错误、危险操作用 `destructive`；成功用 `success`。

当前变量类型处于分阶段迁移状态：

| 类型 | 正确写法 | 用途 |
| --- | --- | --- |
| 完整颜色 | `var(--destructive)`、`text-destructive` | 错误、危险、截止提示 |
| 旧 HSL 通道 | `hsl(var(--background))`、`bg-background` | 页面与普通语义表面 |
| 用户数据颜色 | 日历或标签的 `color` 字段 | 分类色点与日程色块 |

`hsl(var(--destructive))` 会把完整颜色再次包裹成 HSL，属于错误表达式。分类色不直接用于普通文字；分类标签使用语义前景色配色点。实心日程块按用户颜色的
sRGB 相对亮度选择黑／白文字，保证至少 4.5:1 的文字对比度。亮暗主题依赖共享变量，
不另建 Planning 专用主题。新增动画如有必要，进入共享 `animations.css` 并遵守减少动态效果设置。

### 控件与表单

主线 `components/ui/` 提供基于 Base UI 的统一控件：

| 场景 | 采用组件 / 变体 | 业务页仍负责 |
| --- | --- | --- |
| 主要动作、辅助动作 | `Button` 的 default / outline / ghost | 文案、权限、busy 状态 |
| 常规输入 | `Input`、`Textarea`，表单可用 plain | 值、类型、约束、保存 |
| 枚举与筛选 | `Select` | 选项、受控值、可访问标签 |
| 开关式选项 | `Checkbox` | 状态、语义与禁用条件 |
| 月 / 周 / 日切换 | segmented `Tabs` | 当前视图和对应面板 |
| 表单字段 | `FormField`、Label、Description | ID、标签关联、错误提示 |

按钮默认高度为 h-9；紧凑工具栏可用 sm（h-8），图标按钮使用 icon-sm / icon-xs。
不能对页面里所有 button/input 写全局覆盖规则，否则会覆盖这些组件的焦点、禁用与尺寸约定。

### 弹层、状态与响应式

- 编辑使用 `DialogHeader / DialogBody / DialogFooter / DialogActions`，内容区滚动，动作区保持可达。
- 带迁移或删除语义的操作明确描述影响；任务行的回收操作可恢复，编辑器回收及回收站永久删除使用共享 `useConfirmDialog`。
- 低频显示设置用 `Popover`，下拉菜单用 `SelectContent`；层级、碰撞定位和 portal 由共享组件处理。
- 移动端待办区使用 `Sheet`，复用遮罩、焦点管理、Escape 关闭及安全区。
- `useIsMobile` 遵循宿主约定：桌面窄窗为 767px 及以下，Gateway 为 820px 及以下。
- 加载用 `Skeleton`，空列表用 `EmptyState`，错误用 `SettingsNotice`。业务页添加 `role="alert"`
  或 `role="status"`，组件不会自动推断播报语义。
- 表单保存中显式禁用 Select / Checkbox；不只依赖外围原生 fieldset，因为下拉内容会 portal 到外部。

## Planning 的实际调整

| 迁入时的情况 | 本次落地 |
| --- | --- |
| 页面自行画标题和操作样式 | 使用共享控件组成紧凑业务工具栏；加载态使用 `HubHeader`，保留主线常驻顶栏 |
| 原生 button/select/checkbox 配页面通配 CSS | 普通控件改为共享组件；仅网格定位按钮保留专用绘制 |
| 标签包住控件但关联不完整 | `PlanningField` 生成稳定 ID，关联 label 与说明；不改共享 FormField 的职责 |
| 选择项依赖原生 select | `PlanningSelect` 组合共享 Select；items 保证未打开菜单时也显示正确标签 |
| 月周日使用普通按钮 | 使用 segmented Tabs 和对应 tabpanel |
| `<details>` 承担显示设置菜单 | 使用碰撞定位的 Popover；时区用可搜索的 `SettingsCombobox`，编辑框不再提供时区 |
| 自绘移动端遮罩与右栏 | 单份待办内容：桌面 aside，窄屏 Sheet；新建/编辑时关闭 Sheet |
| 保存按钮随长表单滚走 | 使用共享 Footer / Actions，通过 form ID 保留原生表单提交和校验 |
| 删除确认是表单下方临时区域 | 待办/日程改用共享确认弹层；日历迁移删除保留明确目标选择与取消 |
| 局部字号和颜色声明重复 | 标准字号 / 语义颜色；修正 destructive 用法，分类文字改为语义色配色点 |
| 页面 CSS 包含大量控件和弹层规则 | 只保留时间轴、月网格、事件块、拖动/缩放手柄、预览、焦点状态 |

日历排期、重复规则、Agent 执行、存储和跨端协议复用既有能力；回收状态和导入由独立模块扩展。
复杂网格继续引用共享字体和主题；专用按钮保留键盘焦点样式，不强制套用固定高度的普通 Button。

## 后续功能沿用方式

列表菜单使用共享 DropdownMenu，避免标题栏出现多余工具；新增编辑字段使用 PlanningField 加共享控件；新增管理弹层
沿用现有 Dialog 结构。普通布局直接写 Tailwind，跨元素绘制才进入 `planning.css`。
业务分类颜色保留为数据，界面状态颜色使用语义角色。验证同时覆盖 GUI / Gateway 类型检查、
UI 边界和相关行为测试，并对亮暗主题、窄屏及弹层交互进行实际浏览器检查。

验收记录见 [Planning 实现记录](../design/planning-calendar-implementation.md)。

## 参考图的后续吸收

参考用户提供的周日历截图，将日程改为整块分类色，标题强调、时间次之；正文沿用主线字体。
星期、日期与可选农历纵向排列，今天使用语义强调色；弱化列线、去掉半小时装饰线，保留整点刻度。
工具栏显示月份与可选 ISO 周数，时区偏移在时间轴左上角显示。

日程、全天和月视图使用同一个颜色辅助函数；用户日历色不被改写，非法或缺失颜色回退到
主题表面。紧凑块仍可查看完整 tooltip，拖拽、拉伸和键盘焦点保持可用。
保留主线的导航、右侧待办和响应式弹层，参考图的奶油背景与衬线字体不作为全局主题变更。


## Google Calendar / Tasks 参考后的结构

2026-09-27 通过 Chrome 实测 Calendar / Tasks 界面后，改为全面对标布局、层级、交互与尺寸比例
（侧栏、顶栏、周/月/日程视图、任务视图、预览与创建弹窗）；颜色、字体与字号仍服从上面的系统规范。
实测数值与映射见 [Google 对标](../design/planning-google-benchmark.md)。

日历和任务面板位于同一个 flex 行，工具栏在它们之外；面板内部采用 header / 可滚动列表 / completed footer。
任务使用简洁列表行，避免每个任务套独立大卡片。原分组沿用数据 ID 升级为任务列表。
页面可用宽度低于 900px 时任务转入 Sheet，与宿主侧栏是否展开联动；手机日视图保持完整宽度。
月/周网格属于特殊绘制，但弹窗、日期字段、列表选择、回收站、导入状态均使用统一组件。

Google 原本较短的任务标记扩展成可拉伸的时间块：保留独立顶部和底部手柄、键盘调整和视觉预览。
不把任务列表的归属、日历可见性与排期时长混成一个状态。回收是独立数据状态，永久删除只在回收站中提供。

文件与职责清单、导入边界和实际验证结果见 [实现记录](../design/planning-calendar-implementation.md)。


任务交互进一步简化：移除 `CategoryManager` 和标题右侧工具；列表名旁菜单包含星标、列表计数及新建入口，创建弹窗只收集名称。
添加任务采用展开式内联表单（标题、详情、日期时间），无需先打开完整编辑弹窗。
日历已存在的事项先打开 `EventPreview`，通过顶部操作进入编辑或回收，任务预览底部提供完成状态操作。
预览使用共享 Popover 锚定被点击的事项并自动避让边界；不展示应用尚未建模的忙闲、隐私或账户信息。


任务面板进一步收紧：桌面宽度为 288px / 大屏 320px，预览卡片为 320px；减少标题、任务行和表单的纵向留白。
保留共享控件的焦点与点击区域，长标题换行、列表名截断，窄屏仍使用 Sheet。
自建列表的重命名、删除位于列表选择菜单，表单由独立 `TaskListDialog` 负责；星标是筛选视图，不提供删除。
“我的任务”可以删除：需指定新的默认列表，其中任务迁入或移到回收站；之后未指定列表的任务都进入默认列表，删除默认列表会恢复“我的任务”。
删除其他列表前说明任务移到默认列表，保留完成状态与排期；操作携带列表版本，冲突时保留弹窗和错误提示。


### 任务分类和多层子任务

顶部按“日历 / 任务列表”区分普通日程来源与任务分类；任务列表和右侧下拉共用名称、颜色及 ID，创建、重命名、删除即时同步。
任务排期（包含全天、月视图和截止提示）按所属列表独立控制可见性，颜色随列表，移动任务后自动切换分类。
任务标题和详情以 Todo 为准，日历编辑与列表编辑在同一事务内同步，旧独立标题不再覆盖任务；版本冲突仍拒绝覆盖。

`parentId` 支持多层递归子任务，旧数据默认为空。每层共用任务创建、详情编辑、排期、完成与回收操作。任务菜单可继续添加子任务、缩进至前一个同级任务、向左提升一级。
子任务采用右缩进列表并支持展开/收起；父子完成状态独立，跨完成分区时显示父任务名称作为上下文。
移动父任务连同子任务移动；子任务单独移至其他列表时解除父子关系；回收父任务保留子任务并提升为独立任务，保留其排期。
后端拒绝不存在的父任务、自引用、循环与跨列表父子关系，失败时回滚。移动父任务时递归迁移整个子树；回收父任务只提升直接子任务，其后代关系保留。


### 统一时间选择与整行拖拽

`PlanningDateTimePicker` 复用系统 Popover、Button、Input，集中提供月历、今天/明天、全天/定时、开始/结束时间、清除与确认。根任务和所有层级的子任务共用 `TaskComposer`，移除仅支持标题的旧子任务表单。截止时间、排期和重复结束日期也复用该组件；时间转换集中在 `dateTime.ts`，检查结束时间、最小时长与夏令时边界。

任务标题、详情与空白区域均可拖动，无点状拖拽手柄或逐行更多按钮；完成、展开和时间按钮保留点击行为。右键或 Shift+F10 打开任务操作，菜单提供上移/下移作为键盘替代。触屏长按激活拖动。拖入另一任务的上/下半区调整位置与所属层级，拖入日历创建排期，日历时间块可继续移动或拉伸。

排序使用持久化 `sortOrder`，通过 `todo.move` 一次完成子树迁移和兄弟排序，携带任务及落点版本，冲突时整体回滚。切换排序后拖动会恢复自定义顺序。点击与拖动有距离阈值，结束拖动不误触编辑。

### Agent 工具

`PlanningQuery` 在对话、只读计划模式及定时执行中读取日历、任务列表、任务树、排期、提醒和版本。`todoId + includeDescendants` 查询整个子树，`parentId` 查询直接子任务（null 表示根任务），支持按任务列表、日历、日期范围过滤。

`PlanningMutate` 注册明确操作白名单，支持日历/列表/任务/日程/提醒的创建与修改、任务排序与层级迁移、排期、回收和恢复、日历导入及默认时区调整。写操作沿用工具权限、幂等请求 ID 和版本检查；永久删除必须来自用户明确请求。工具定义与实际后端操作保持一致，排期编辑中的标题和详情在同一事务更新所有关联展示。


### 与 Google 的后续对齐（2026-09-28）

- 页面沿用 Hub 页的响应式左右留白，但不设 1320px 上限，日历铺满可用宽度。
- 创建统一为快速创建卡片：网格点选、拖选、侧栏「创建」和快捷键 C 都在对应时段（或当前时间）画出占位块并锚定 Popover；「更多选项」带着已填内容进入完整编辑框。
- 任务在快速创建中带时间段（即排期块）和可选截止时间；截止时刻在网格中显示为浮于日程之上的单行胶囊，不参与日程的并列布局。
- 活动的提醒改为「通知：N 分钟前」，默认跟随日历；编辑框不再提供时区选择和手动指定时刻的提醒，预览卡片不显示时区。
- 标签只在存储层保留兼容，界面与 Agent 工具均不暴露。
- 时间密度设置移除，日/周视图每小时最少 48px，随窗口拉伸。
- 业务 `DropdownMenuItem` 自行加 `gap-2`（共享项默认无间距，与其他页面一致）；列表菜单左列统一放图标或色点，数量与选中勾选靠右。
- `text-tiny` 只用于日期数字、计数徽标等紧凑数字；说明性文字（农历、议程元信息、月视图星期、面板标题）用 `text-xs`。
- 缺失或非法的日历颜色回退到主题表面，不写死色值。
