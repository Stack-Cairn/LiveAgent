## 拆分与维护边界

- `PlanningPage`：页面编排、数据订阅、日期范围、编辑入口、拖动提交和撤销。
- `PlanningToolbar` / `CalendarDisplaySettings` / `calendarDisplay`：工具栏、偏好与日期显示算法。
- `TimeGrid` / `MonthGrid` / `eventAppearance`：日历几何、交互、分类色对比度。
- `TaskPanel` / `TaskRow`：列表状态、分页、单项操作。
- `TaskListMenu` / `TaskComposer`：紧凑列表菜单、名称创建弹窗、内联添加表单。
- `EventPreview`：事项只读预览及显式编辑、回收、完成操作。
- `PlanningEditor` / `CalendarManager`：事项编辑与日历管理。
- `PlanningTrash` / `CalendarImport`：集中回收管理、来源文件预览及导入。
- Rust `trash.rs` / `calendar_import.rs`：回收状态约束与事务导入；共用 `store.rs` 的 revision、幂等、验证及持久化。

普通表单、菜单和弹层复用共享 UI 组件。`planning.css` 只保留网格、事件、指示线、拖动手柄与焦点样式。

## 回收站与一致性

Todo 和 Event 新增可选 `deletedAt`，旧 JSON 数据默认未删除，无需破坏性迁移。

- `todo.delete` 隐藏任务及关联排期、停止待处理提醒；`todo.restore` 保留原状态、列表、排期恢复。
- `event.delete` 隐藏单个日程或整个重复系列；`event.restore` 恢复。单次重复实例的删除保存为可恢复的例外。
- `todo.purge` / `event.purge` 仅可永久删除回收站条目；前端明确确认，不提供自动清空。
  永久删除任务一并清理排期和来源关联，避免任务消失后排期作为孤立日程重新出现。
- 已回收事项不可编辑或排期。恢复例外或关联日程前，须先恢复其系列/任务。
- 修改已完成任务不会重写原完成时间；取消完成清除完成时间。恢复时未来提醒重新启用，已确认提醒不重发。
- 所有 mutation 仍要求匹配的 revision；冲突提示重新读取，不静默覆盖。

## 外部日历、Google Tasks 与邮件邀请导入

`ical.js` 解析 ICS，`postal-mime` 提取 EML 邮件内的 `text/calendar` / `.ics` 邀请附件，`jszip` 直接读取压缩包。
支持的文件：`.ics`、`.eml`、Google 日历「导入和导出」得到的 `.zip`（每个日历一个 `.ics`）、
Google Takeout 的 `Tasks.json` 或整个 Takeout `.zip`。不读取邮箱账户，也不会发信。

1. 用户选择可写目标日历（仅日程需要）、日期范围和本地文件。
2. 客户端解析后预览日程与任务数量和前 100 条，并列出被跳过事项的原因；原始文件不会提交到 Agent。
3. 保存时按每批 200 条依次提交：日程走 `calendar.import`，任务走 `todo.import`；任务按父任务在前排序，
   后续批次可以挂到前面批次的父任务下。
4. Rust 原子保存每一批：日程以「目标日历 + UID」去重（`ical` 来源），任务以 Google 任务 ID 去重
   （`google-tasks` 来源），包括已在回收站中的条目。

任务导入规则：Google 默认列表（My Tasks / 我的任务）归入「我的任务」，其他列表按名称匹配已有任务列表，
不存在则新建；截止日期取日期部分并使用当前时区；已完成任务保留完成时间；子任务只在父任务同列表时保留层级；
空标题和已删除的任务跳过。

上限：单文件 10 MB、压缩包 100 MB、日期范围 366 天、单次最多 5000 条；密集重复规则有迭代上限。
重复规则、EXDATE 和例外在所选范围展开成独立副本，来源键保留原实例身份。
取消邀请不会被当成新日程导入。文件导入是一次性的，需要持续同步请使用订阅。

## iCal 订阅

设置 → 资源与自动化 → 日历 →「订阅日历」：填写 iCal 链接（Google「iCal 格式的私密地址」、Outlook、
Apple 等；`webcal://` 自动转为 `https://`）、名称、颜色和刷新间隔（15 分钟～每天）。

- 订阅日历为只读日历（`sourceKind = "subscription"`），显示在侧栏「其他日历」，不产生提醒。
- 链接只保存在桌面端 `planning_subscriptions` 表，不进入快照：WebUI、备份导出和 Agent 工具都看不到，
  快照只带 `subscriptions` 状态（主机名、间隔、上次同步时间、错误）。
- 桌面端 `PlanningSubscriptionRunner` 每分钟及数据变化时认领到期订阅（带 10 分钟租约），后端经应用代理下载
  （30 秒超时、10 MB 上限），前端用与文件导入相同的 ICS 解析器展开「过去 30 天～未来 365 天」，
  再由 `planning_subscription_sync` 原子镜像：按 UID 新增或更新，源中已消失的日程删除。
- 失败时保留上一次成功的内容，记录错误码（界面按语言显示），最多 1 小时后重试；「立即刷新」会重置到期时间。
- WebUI 可以添加、修改、刷新和取消订阅（`subscription.*` 经 Gateway 透传），实际下载只在桌面端进行。
- 备份恢复不包含订阅链接；恢复后没有对应日历的订阅记录会被清理。

不做 OAuth 账户登录或双向同步；订阅日历只能在来源服务中修改。

## 既有能力与协议

- SQLite 是权威存储；事务、对象 revision、requestId 幂等、全局 seq 与 JSON 备份接口保留。
- Gateway v2 请求/响应/失效事件透传规划数据；桌面与 Web 共享 UI，按目标 Agent 隔离镜像，断线重新查询。
- 标签仅保留在存储层（兼容旧数据与备份），界面与 Agent 工具均不再暴露。
- 系统提醒、应用内确认/推迟、通知租约和重试保留。
- `PlanningQuery` 默认隐藏已回收数据；`includeTrash` 可查询回收站。`PlanningMutate` 支持恢复与永久删除，后者要求用户明确提出。
- 外部来源关系不授予发信能力。

### 任务分类和多层子任务

顶部按“日历 / 任务列表”区分普通日程来源与任务分类；任务列表和右侧下拉共用名称、颜色及 ID，创建、重命名、删除即时同步。
任务排期（包含全天、月视图和截止提示）按所属列表独立控制可见性，颜色随列表，移动任务后自动切换分类。
任务标题和详情以 Todo 为准，日历编辑与列表编辑在同一事务内同步，旧独立标题不再覆盖任务；版本冲突仍拒绝覆盖。

`parentId` 支持多层递归子任务，旧数据默认为空。每层共用任务创建、详情编辑、排期、完成与回收操作。任务菜单可继续添加子任务、缩进至前一个同级任务、向左提升一级。
子任务采用右缩进列表并支持展开/收起；父子完成状态独立，跨完成分区时显示父任务名称作为上下文。
移动父任务连同子任务移动；子任务单独移至其他列表时解除父子关系；回收父任务保留子任务并提升为独立任务，保留其排期。
后端拒绝不存在的父任务、自引用、循环与跨列表父子关系，失败时回滚。移动父任务时递归迁移整个子树；回收父任务只提升直接子任务，其后代关系保留。


### 统一时间选择与整行拖拽

`PlanningDateTimePicker` 复用系统 Popover、Button、Input，集中提供月历、今天/明天、全天/定时、开始/结束时间、清除与确认。根任务和所有层级的子任务共用 `TaskComposer`，移除仅支持标题的旧子任务表单。截止时间、排期、重复结束日期和独立提醒也复用该组件；时间转换集中在 `dateTime.ts`，检查结束时间、最小时长与夏令时边界。

任务标题、详情与空白区域均可拖动，无点状拖拽手柄或逐行更多按钮；完成、展开和时间按钮保留点击行为。右键或 Shift+F10 打开任务操作，菜单提供上移/下移作为键盘替代。触屏长按激活拖动。拖入另一任务的上/下半区调整位置与所属层级，拖入日历创建排期，日历时间块可继续移动或拉伸。

排序使用持久化 `sortOrder`，通过 `todo.move` 一次完成子树迁移和兄弟排序，携带任务及落点版本，冲突时整体回滚。切换排序后拖动会恢复自定义顺序。点击与拖动有距离阈值，结束拖动不误触编辑。

### 多语言与命名

页面对外名称为「日历 / Calendar」（`settings.navPlanning`），避免与聊天的「计划模式」混淆；代码与工具标识（`planning-hub`、`PlanningQuery`）不变。

界面文案位于 `agent-ui/src/i18n/planningTranslations.ts`（`planner.*`，中英文键一致，由 `test/i18n` 校验）。组件使用 `usePlanningT()`，纯函数使用 `lib/planning/i18n.ts` 的 `translate()`；日期、星期、月份按界面语言经 Intl 格式化，农历仅在中文界面提供。

后端（Rust）不感知界面语言：错误返回稳定错误码 `E:<code>` 或 `E:<code>:<detail>`，前端在数据层用 `localizePlanningError` 翻译为 `planner.error.<code>`，Agent 工具收到英文。提醒通知标题由前端经 `planning_set_labels` 下发；首次初始化的默认日历「工作 / 个人」在未改名前按界面语言显示。

### 与定时任务隔离

日历只管理日历、日程与任务，不绑定项目、不启动或关联 Agent 会话，也不展示定时任务；自动执行统一由定时任务负责。
预发布版本的项目绑定（`projectId`）与会话关联（`links`）在读取旧数据或导入旧备份时被接受并丢弃，不再写入；
`planning_agent_runs` 执行队列、`planning_integration` / 认领 / 完成命令及定时任务执行器中的日历分支均已移除，定时任务行为与 main 一致。

### Agent 工具

`PlanningQuery` 在对话、只读计划模式及定时执行中读取日历、任务列表、任务树、排期、提醒和版本。`todoId + includeDescendants` 查询整个子树，`parentId` 查询直接子任务（null 表示根任务），支持按任务列表、日历、日期范围过滤；`starred` 与 `overdue` 分别对应界面的「已加星标」和今天的「N 项待处理任务」。

`PlanningMutate` 注册明确操作白名单，支持日历/列表/任务/日程/提醒的创建与修改、任务排序与层级迁移、排期、回收和恢复、日历导入及默认时区调整。写操作沿用工具权限、幂等请求 ID 和版本检查；永久删除必须来自用户明确请求。工具定义与实际后端操作保持一致，排期编辑中的标题和详情在同一事务更新所有关联展示。
