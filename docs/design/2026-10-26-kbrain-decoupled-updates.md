# LiveAgent 与 K-brain 解耦更新设计

日期：2026-10-28。状态：设计草案，尚未实施。本文与 [K-brain 兼容契约（PR #59）](https://github.com/Stack-Cairn/K-brain/pull/59) 配套；K-brain 侧正文路径为 `docs/compatibility.md`。本文定义 LiveAgent、Gateway 与 WebUI 如何选择、验证和切换兼容的后端版本。

## 1. 目标、范围与选择

LiveAgent 没有前端改动时，用户可以独立安装兼容的 K-brain 修复。更新应保持旧功能的行为，明确告知数据兼容边界，并在可恢复的失败中保留可用版本。桌面端、浏览器直连、Gateway 远程会话、生图实例和独立 TUI 都在范围内。

本 PR 只有设计文档。文中的字段、命令和状态均为拟新增契约，除“源码依据”节明确列出的现状外，不表示代码已经支持。

| 选择 | 收益 | 代价与结论 |
|---|---|---|
| 继续随 LiveAgent 锁定后端 | 安装组合确定，运维简单 | 后端修复仍需重发桌面安装包，保留为离线基线 |
| 按协议主版本直接追随 K-brain 最新版 | 修复传播快 | 无法单靠协议判断存储和行为兼容，不采用 |
| 按契约与本机状态选择独立版本 | 修复可以独立分发，升级条件可审计 | 需要发布签名、存储检查和跨版本测试，作为本文方案 |

默认更新方式为“下载后提示”，另提供“只手动检查”和用户主动开启的“下次启动自动切换”。频道默认跟随 LiveAgent，用户可以固定后端版本。数据迁移另设确认，不随自动更新开关一并授权。

### 1.1 必须保持的规则

| 编号 | 规则 |
|---|---|
| U1 | 执行下载的二进制（包括 `-version`）前，先用内置公钥验证更新目录和发布清单的 minisign/Ed25519 签名，再按已验签清单校验 backend 与 helper 的文件大小和 SHA-256；此要求不依赖 Windows Authenticode 代码签名 |
| U2 | 兼容性同时取决于协议、能力、平台、启动契约和当前存储状态 |
| U3 | 历史共享目录不做原地破坏性迁移，不承诺旧二进制能识别新门禁 |
| U4 | 迁移未完成的目标目录不对普通进程开放，启动失败不能绕过恢复 |
| U5 | 切换前停止接受新任务并排空全部入口，失败写请求不得自动重放 |
| U6 | 回退要同时验证客户端兼容和存储可读写，不能只看版本新旧 |
| U7 | 权限功能缺失时保持授权约束，不能静默替换成更宽松模式 |
| U8 | 更新状态由当前规范化数据根下的单一协调者修改，多实例共享互斥 |

## 2. 两个仓库的职责

K-brain 维护对外契约、存储检查和迁移实现，发布带签名的清单与频道目录。LiveAgent 读取这些声明，管理下载和进程，不自行解释、修改 K-brain 业务文件。Gateway 不下载远程后端，由部署者固定镜像或版本。

| 事项 | K-brain | LiveAgent / Gateway |
|---|---|---|
| 协议与能力 | 定义语义，确保旧调用仍成立 | 探测能力，选择适配器，提供降级 |
| 数据 | 判断可读写性，生成计划，导入与恢复 | 显示计划和确认，传递不透明令牌 |
| 更新 | 发布不可变产物及签名元数据 | 验证、选择、下载、保留版本 |
| 进程 | 持有存储租约，提供任务排空协议 | 独占切换，监视退出，刷新连接 |
| 测试 | 存储、TUI、服务端旧契约 | 真实旧客户端、传输恢复、平台打包 |

版本选择与数据迁移是两个步骤。签名证明清单由受信发布者签发，不能证明声明正确。两仓库的兼容测试仍是发版门禁。

## 3. 协议、能力与支持范围

### 3.1 连接判断

主版本 1 中，health、响应与 SSE 的旧 `version` 保持 `kbrain.agent.v1`。新增 `protocol` 与旧字段矛盾时拒绝连接。只有旧字段确为 v1 且新字段缺失时，才按兼容旧后端处理；字段类型错误不能当作缺失。

LiveAgent 按协议代际选择完整适配器，不能仅让握手接受 v2，却继续用 v1 解析响应。协议、启动契约、发布清单 schema 分别版本化。未知 schema 或缺少必要字段的 release 不参与更新，已运行后端不受影响。

### 3.2 能力表示与降级

`session_queue`、`session_exists`、`memory_switch`、`image_model_toggle`、`computer_session_approval` 的历史值固定为 `1`。增强使用新名字，避免破坏旧客户端的 `!== 1` / `!= 1` 判断。`permission_modes` 继续是列表，`image` 继续是对象。`session_changes` 已有客户端使用 `>= 2`，其能力定义允许单调整数升级，不能把这一规则套到全部历史字段。

新能力首次登记时写明字段类型、比较方式和缺失行为。静态能力与运行时可用状态分开。静态能力不倒退，`image.supported` 等运行状态可以改变。能力快照携带实例标识和修订号，不把配置失效解释成协议换代。

| 功能 | 能力缺失时的行为 |
|---|---|
| 会话存在检查 | 使用已有迁移路径，不把未探测误判为会话不存在 |
| 会话变化同步 | 缺 `session_changes >= 2` 时停用增量同步，回到既有刷新路径 |
| 后端队列 | 新会话可用旧执行方式；已经由后端拥有的队列不能转交，显示阻塞原因 |
| 权限模式 | 保存的模式无对应能力时阻止该次发送，允许用户明确改为逐次确认 |
| 记忆、生图设置 | 隐藏或禁用不可用控件，保留用户原值，不发送未知字段 |
| Computer Use 会话授权 | 缺少对应选项时逐次授权，不推导为始终允许 |
| 新服务端修复 | 没有新增客户端行为时无需新增能力，仍受旧行为回归测试约束 |

### 3.3 支持窗口

首个启用更新器的 LiveAgent 记为 L0，首个实现本契约的 K-brain 记为 K0。发布前必须把符号换成真实 tag，禁止猜测尚未发布的版本号。

协议 1 的兼容承诺覆盖已登记的 v2 客户端契约，不按发布时间随意删除。每次 K-brain 候选发布至少运行最早支持客户端、最新 stable、最新 prerelease 和 Gateway 的真实适配器测试。移除支持需要协议主版本变化。

同时提供安全维护的协议线最多两条。新协议正式发布后，旧线至少维护十二个月。终止维护提前九十天公告。超过窗口的客户端可以继续使用已有离线版本，但不能宣称仍收到安全更新。频道目录保留其最后可用条目和升级说明。该维护预算需由两仓库维护者在启用发布流水线前接受。

## 4. 发布、签名与候选选择

### 4.1 信任来源

这里的签名是 K-brain 发布方用项目私钥对更新元数据生成的 minisign 签名，由 LiveAgent 内置公钥验证。它与 Windows Authenticode 代码签名分别管理。本方案允许 Windows EXE 和安装包没有 Authenticode 签名，不以购买代码签名证书或获得微软签名作为独立更新的前提。

| 校验对象 | 验证材料 | 更新器检查 |
|---|---|---|
| 更新目录 `channels.json` | `channels.sig` 与内置 K-brain 公钥 | 验证 minisign 签名，再检查版本列表、有效期和撤回记录 |
| 发布清单 `release-manifest.json` | `release-manifest.sig` 与内置 K-brain 公钥 | 验证 minisign 签名，并核对目录绑定的清单摘要 |
| backend 与 computer helper | 已验签清单中的大小和 SHA-256 | 校验实际文件与清单一致，然后才允许执行 |

这套元数据签名及自动验签流程是拟新增设计，当前尚未实现。它不会让 Windows 把 EXE 识别为具有 Authenticode 代码签名的程序，也不保证消除 SmartScreen、未知发布者或安全软件提示。操作系统是否允许执行仍需单独验证，相关拦截按启动故障处理。

采用 minisign 的 Ed25519 detached 签名格式，Rust 使用 `minisign-verify` 验证，不自行实现密码运算。K-brain 使用专用签名密钥，不能复用 LiveAgent 更新私钥。公钥与 key ID 随 LiveAgent 安装包进入只读信任配置。初期密钥轮换通过 LiveAgent 发版分发。新公钥先到客户端，发布端再换签。未知 key ID 只提示升级客户端，不动态信任 release 携带的公钥。

签名覆盖清单的原始 UTF-8 字节，调用方先验签再解析。JSON 拒绝重复键。清单上限 256 KiB，频道目录上限 8 MiB，签名封装上限 8 KiB。频道目录也签名，包含单调序号、有效期、候选清单摘要与撤回记录。`kind` 与仓库字段防止把另一类签名文件当成清单。清单和签名来自同一服务器不影响独立验签，但签名密钥泄露仍需客户端信任更新，不能声称完全消除供应链风险。

`SHA256SUMS` 可保留给人工使用。自动更新以已验签清单中的资产大小和 SHA-256 为准，不依赖同源无签名校验和建立信任。

### 4.2 获取顺序

1. 获取频道目录和 detached 签名，验签并检查有效期、schema、目录序号。
2. 验证目录中候选清单的摘要及签名。候选排序使用签名的 `releaseSequence`，tag 只作身份标识。
3. 按频道、平台、协议适配器、启动契约、撤回状态、固定版本和本地失败记录过滤。必须遍历全部合格候选，不能发现最新一条不兼容就停止。
4. 下载同一清单绑定的 backend、computer helper。检查大小和摘要，完成后才允许执行版本查询。
5. 调用 K-brain 只读存储规划命令，根据本机数据决定普通更新、确认迁移或拒绝。

目录序号按仓库和更新源保存，不按频道保存，防止切换频道回放旧撤回记录。过期、回放、网络失败或系统时钟明显异常时停止新的自动安装，保留现有离线启动能力，不猜测“最新”。显式回退可以选择目录仍允许的旧版本，不降低已经接受的目录序号。

元数据 URL 固定为官方仓库。二进制下载允许 GitHub 正常使用的 HTTPS 资产重定向，最终内容仍须匹配签名摘要。禁止向重定向目标传递后端令牌。路径来自本地平台映射和受限资产名，拒绝路径穿越、符号链接和压缩包任意解包。

### 4.3 发布错误与撤回

撤回通过更高序号的签名目录发布，写明安全撤回或普通质量撤回。撤回项停止新安装，清除对应 pending。运行中的版本被安全撤回时明确提示并要求切换。不在模型或工具操作中途强杀。离线时无法及时获知撤回，这一限制必须保留。

本地 `bad` 记录按清单摘要、平台、错误类别和尝试次数保存。网络、忙碌、用户取消不标坏。清单声明错误或确定性启动失败可隔离版本，用户重试前展示原因。修复产物必须发新 tag，禁止原 tag 替换文件后当作同一版本。

## 5. 存储边界与迁移确认

### 5.1 两类数据目录

原 `~/.liveagent` 或环境变量指定的数据根记为 G0。没有新标记时按历史格式处理，绝不能据此推断所有写入者支持新锁。G0 允许经过往返测试的兼容更新，禁止原地提高最低读写要求。

需要破坏性格式的版本使用新代际 G1，路径位于协调根的 `kbrain/data/<generation-id>/`。旧 `kn` 继续使用 G0，无法误写 G1。新版 TUI 通过显式数据目录参数选择 G1。默认保持 G0，LiveAgent 不修改 PATH、shell 环境或 TUI 默认指向。

切换界面必须说明旧 TUI 与新后端将使用两份数据，修改不会自动同步，并给出指定 G1 的启动命令。拒绝切换就继续使用 G0 的可用版本。不得用“不影响 TUI”掩盖数据已分流的事实。

### 5.2 迁移计划

K-brain 是格式判断的唯一责任方。LiveAgent 可读取固定格式的只读诊断，但不得自行以 `storage.version >= minReader` 推导可写性。每个二进制分别声明可读、可写格式集合，实际规划还要检查目录中的迁移状态。

拟新增 `kn storage plan -data-dir <source> -target-dir <new-generation> -target-manifest <verified-manifest> -format json`，仅读取标记及元数据，不修复、不创建目录、不获取模型凭据。输入已经是快照时，用 `-snapshot <path>` 替代 `-data-dir`，两种输入互斥。规划的 JSON 契约见配套文档第 5 节。

规划必须覆盖当前格式到目标格式的全部迁移边，返回计划 ID、源修订、目标要求、迁移步骤、是否需要独占、是否可回退和风险说明。清单只声明目标格式及支持范围，不再用单个 release 的 `migration: none` 决定本机是否安全。

用户确认绑定计划 ID、源存储身份与修订、目标清单摘要、代际和备份摘要。确认后源数据或计划改变，原确认失效。不要在下次启动复用含义不同的确认。

### 5.3 快照与恢复

迁移在新目录进行，不修改 G0。输入必须是已验证的一致性快照。K-brain 的导出器需要对每个可变子系统建立一致性边界。只检查文件哈希、按进程名扫描或复制后比较大小，都不能替代该边界。执行前重新检查快照摘要和目标清单，导入使用 `kn storage import`，中断后使用 `kn storage recover`，准确参数见配套契约第 6.5 节。

历史程序无法遵守统一排空或锁时，不提供无人值守的破坏性迁移。用户先关闭写入者，按导出工具要求建立离线快照。工具无法证明子系统一致性就拒绝生成可迁移快照。没有受支持导出路径的源格式，显示“暂不能迁移”，保留兼容更新，不能尝试带风险的自动复制。

快照生成后，源目录仍可以被旧 TUI 使用。导入代表快照时刻的数据，不追赶之后的改动。目标导入需要 journal，步骤幂等，完成业务一致性检查后才写入 ready 标记。中断目标保持不可用，只能恢复或显式放弃目标。源数据保持原状。

切回 G0 只是切回旧快照来源，G1 上的新工作不会被自动合并。界面必须区分“二进制回退”和“切换数据代际”，后者单独确认，避免用户误认为新数据已经恢复到旧格式。

## 6. 本地目录与多实例

```text
<coordination-root>/kbrain/
  update.lock
  state.json
  artifacts/<manifest-sha256>/
    k-brain[.exe]
    k-brain-computer[.exe]
    release-manifest.json
    release-manifest.sig
  staging/<transaction-id>/
  data/<generation-id>/
  diagnostics/update.jsonl
```

协调根是启动时规范化后的 `LIVEAGENT_HOME`、兼容别名 `K_BRAIN_HOME` 或默认根。任务开始后环境变化不隐式切换数据根。路径包含 junction/symlink 时按真实路径建立存储身份。不支持的网络文件系统拒绝托管切换，不以不可靠文件锁冒充互斥。

安装包携带锁定后端、helper、对应已签名清单和摘要。首次使用时以事务方式导入 artifacts，复制后的摘要必须仍匹配清单。平台资源位置通过 Tauri resource API 或显式打包映射解析，不能假设 manifest 永远在 externalBin 旁边。macOS、Windows 安装与 portable、Linux AppImage/deb 都要验证实际安装布局。

同一规范化根只允许一个托管后端所有者。它持有协调锁；第二个 LiveAgent 实例报告占用，不创建另一个托管进程，也不修改更新状态。调试与正式版共存应显式配置不同协调根。远程 Gateway 由其运维控制，与本地协调者不互相接管。

存储共享租约允许新版 TUI 正常并用；切换需要独占启动检查，TUI 占用时可下载但不能完成切换。排空后停止旧后端以释放它自己的共享租约，新候选使用 `-exclusive-start` 获取独占租约、重检格式和 journal，再降为共享租约，最后发布就绪信号。独占降级若平台不是原子操作，重取共享租约后必须再次检查修订与状态。协调锁的跨进程顺序固定为协调锁、存储租约、进程内部锁。所有入口遵守顺序，禁止持有内部锁等待迁移确认。

state 中记录 schema、目录序号、active/pending/previous 的清单摘要和代际、切换事务、验证状态与本地隔离记录。写入采用同目录临时文件、同步数据和原子替换。进程退出锁由操作系统释放，PID 文件仅用于诊断。state 损坏时保留原文件，不扫描目录后猜测 active。只根据完整切换事务与存储检查恢复，否则要求用户选择组合。

## 7. 更新与切换状态机

```text
Idle -> Discovering -> Verified -> Downloaded -> Planned
Planned -> AwaitingConsent | Pending | Blocked
AwaitingConsent -> Pending | Idle
Pending -> Draining -> Switching -> Probation -> Active
Switching -> Recovering -> Active | Blocked
Probation -> Recovering | Active
```

| 状态 | 持久化与动作 | 取消、失败或重启后的处理 |
|---|---|---|
| Discovering / Verified | 只保存已接受的目录序号和元数据 | 网络失败不影响 active；未验签数据不得执行 |
| Downloaded | 保存完整产物及摘要，不改 active | 取消可保留已验证缓存，半下载只能续传后重新全量校验 |
| Planned | 保存本机计划与源修订 | 计划过期重新规划；忙碌等待，不标 bad |
| AwaitingConsent | 展示版本、来源、数据影响、权限变化 | 拒绝不改活动组合，重复点击复用同一事务 |
| Pending | 原 active 和 previous 仍有效 | 频道、固定版本或撤回变化时重新检查，不强行切换 |
| Draining | 原后端拒收新任务，所有生产者进入排空 | 超时取消切换并重新开放原后端，不强杀任务 |
| Switching | 先持久化待尝试组合，再停止旧进程 | 崩溃后协调者读事务恢复，不能猜测哪份状态已提交 |
| Probation | 候选可响应业务，previous 尚不删除 | 启动和崩溃故障按存储规则回退，业务请求不自动重放 |
| Active | 提交新活动组合及观察结果 | 保留 previous、安装包基线和仍被引用的数据代际 |
| Recovering / Blocked | 保留诊断和失败的确切阶段 | 迁移中断先恢复；无安全候选时明确阻塞 |

### 7.1 排空范围

排空由 K-brain 统一统计，覆盖桌面会话、Gateway、队列、Cron、后台规划、生图和 Computer Use。仅检查当前聊天页空闲不够。拟新增排空令牌：停止新任务受理和后台调度，等待已有操作到达持久化安全点。排队中的任务保留，恢复后不重复接受。

发起排空后仍有并发请求到达，K-brain 返回可识别的暂不可用错误，客户端保持原请求 ID。读取可以在连接恢复后重试；写入只允许查询已有受理记录，不能生成新 ID 重放。

默认排空等待三十秒，可以由用户取消。未排空就留待下次启动。TUI 不响应托管排空时，以其存储共享租约阻止独占切换，提示关闭 TUI。重启电脑之后也要重新规划和检查租约。

### 7.2 就绪与观察

候选启动验证包括进程启动、就绪信号、真实 build 身份、协议、必要基础接口、目标存储 ready 和本机平台可执行性。基础探测不调用模型、不创建 run、不操作用户文件。helper 的实际握手在隔离自测中完成，不能用 health 代替 helper 可用性。

普通启动每次十五秒，默认最多三个不同组合尝试，总预算六十秒。迁移不塞进启动超时，单列进度和取消条件。Rust 推送真实进度，前端展示总预算和当前尝试。丢失进度事件也不能无限延长等待。

观察期为启动后十分钟，累计运行时长跨短暂重启记录。候选在两分钟内两次非用户导致的退出可触发回退。观察期通过表示启动稳定，不声称所有业务兼容。接口 500、事件语义错误和模型输出变化进入诊断与手动回退流程，不把 HTTP 错误一律当作坏版本。

## 8. 安全回退与缓存保留

回退目标依次为同一数据代际的 previous、该代际已验证的安装包基线。目标必须仍允许安装，协议适配器存在，且 K-brain 存储规划确认可读写。若只能找到另一个代际，需要用户确认数据切换，不进入静默回退链。

退出码只表示故障类别，不直接命令回退。75 表示租约或目录忙；76 表示不可安全读写；77 表示迁移未完成；78 表示需要显式迁移批准。上述情况都不因一次出现就标 bad。迁移 journal 优先于候选选择，禁止删除标记后强启旧二进制。

切换恢复使用已持久化事务判定候选是否曾对业务开放。候选已经受理写入后，回退只能选择可安全读写同一存储的版本。若其格式要求已变化，保留进程与数据并显示恢复指引。不能为提高启动成功率绕过门禁。

清理以引用为准。active、previous、pending、安装包基线和恢复事务引用的产物均保留。未引用产物可在成功切换后清理，正在执行的文件不可删除。数据代际和快照不随二进制垃圾回收删除，需要用户独立操作。

## 9. Gateway、WebUI 与浏览器直连

会话实例和生图实例分别握手、缓存与刷新。缓存键包含规范化 endpoint、认证身份和实例标识，不把两个后端能力合并后发送给所有页面。经桌面桥接时，由桌面传递它所连接的实例状态，远程模式不隐式改连本地。

Gateway 启动、SSE 重连、endpoint 或令牌变化时重新取 health。正常缓存有效期三十秒，使用依赖新能力的写请求前，若缓存超过五秒就重新验证。health 报告 `instanceId`、`capabilityRevision`。新请求携带 `X-Kbrain-Instance`，支持本契约的后端在不匹配时于执行前拒绝，客户端刷新后只重试尚未受理的请求。

历史后端没有实例条件检查时，运维必须在单实例停机升级与请求排空后替换，不支持同一地址混跑能力不同的副本。健康快照不能消除“探测后即替换”的竞争，这个限制要写进部署文档。旧后端能力缺失仅禁用相关功能，不默认伪造空列表覆盖用户设置。

能力与连接更新下发给 WebUI，页面重新计算控件状态。权限模式丢失时阻止发送并提示，不能沿用已失效的 auto_review。SSE 仍按原 run 和 after_seq 恢复。版本更新不产生新 run。浏览器直连采用相同规则。

Gateway 容器通过不可变 digest 固定 K-brain 镜像或资产清单。部署说明应覆盖配置、令牌、数据卷、排空、备份验证、升级和同代际回退。数据要求更高时不得只换镜像。生图与会话服务分开列出当前 build 和兼容状态。

## 10. 设置与诊断

设置显示 LiveAgent 版本、K-brain tag/revision、清单摘要、协议、能力修订、平台与资产来源。存储信息显示逻辑代际、格式和可回退范围，路径默认做隐私遮盖。固定版本与关闭自动下载是两个设置，不能互相覆盖。

操作包括检查、下载、确认切换、取消 pending、重试、同代际回退和恢复安装包基线。任务运行、TUI 占用、撤回、目录过期和迁移中断分别显示原因。安装包基线不兼容当前存储时按钮禁用并解释，不能让“恢复自带版本”变成强制启动。

日志按事务写入时间、状态、清单摘要、实例、错误 code 和恢复结果。token、模型凭据、提示词和用户文件内容不入日志。诊断导出先给用户预览，保留可复现的版本组合和脱敏状态，不自动上传。

## 14. 发布前必须落实的条件

签名密钥保管和双协议维护预算需要维护者落实。缺少其中任一项时，自动更新保持关闭，手动导入也不能绕过验签。快照导出、跨平台租约、迁移 journal 与实例条件检查都需要代码和故障测试支持，文档本身不能充当保证。首次携带破坏性格式的新安装包，也必须走同一存储规划与确认。没有旧产物的用户拒绝导入后进入说明界面，不能静默改写 G0。

隔离代际会使旧 TUI 与新后端的数据分流，这是保留历史程序可用性的明确代价。若产品要求它们永久共享同一份可写数据，则必须继续约束存储格式兼容，不能同时承诺任意破坏迁移和所有旧二进制可用。
