# CLI 身份更新日志

目标版本：`v1.3.0`（开发版本 `1.3.0-dev.0`）

## 新增功能

- 在供应商设置中统一管理 Anthropic、OpenAI 和 Grok 请求使用的 CLI 版本身份。
- 提供「内置兼容」「更新时确认」「自动跟随」三种策略，默认检测到更新后由用户在软件内确认。
- 应用启动、窗口重新聚焦及长时间运行期间会检查官方稳定版本；手动检查可随时立即刷新。
- 更新后的 User-Agent 对新请求立即生效，无需重启应用，并支持回滚到上一版本。
- 供应商请求页会显示实际生效的 User-Agent，以及全局身份、自定义覆盖或协议不注入状态。

## 更新行为边界

- 回滚即视为否决该版本：自动跟随模式不会再把它装回去，但更高的新版本仍照常跟随；用户在确认模式下手动重新应用同一版本即撤销否决。
- 「内置兼容」模式恒用内置版本，因此不显示可更新提示——提示了也无法应用。
- 检查失败只记录失败时间并进入 1 小时退避，不写入上次检查时间；否则离线时每次窗口聚焦都会重新发起请求。

## 安全与兼容

- 在线检查只访问固定 npm 官方包与 dist-tag，不接受用户提供的远端地址。
- 远端响应只读取稳定 SemVer 版本号，完整 User-Agent 始终在本地生成。
- Gateway WebUI 通过带鉴权的同源接口查询版本，避免浏览器跨域限制；服务端使用固定供应商白名单、响应大小限制和稳定版本校验。
- 自定义 User-Agent 保持最高优先级；Anthropic OAuth 与 Codex Chat Completions 继续遵循原有协议例外。
- CLI 身份通过供应商运行时配置工厂传播到聊天、标题、记忆、Cron 与子代理继承链路，基于已合并的请求头传播修复 PR `#289`；该工厂的身份参数为必填，新增调用点漏传会直接编译失败而不是静默丢头。
