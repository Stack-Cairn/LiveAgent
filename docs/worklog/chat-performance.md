# 长会话性能与历史加载

## 修改

- 历史分页移除请求完成、页面提交及 `scrollend` 后的自动连锁检查。滚轮、键盘和触摸向上阅读可触发下一页；同一边界和进行中的请求合并处理。保留原有虚拟列表锚定，并处理原生滚动位置停留在零、逻辑位置已经移动的情况。
- 虚拟列表关闭滚动事件中的同步 React 提交（`useFlushSync: false`），保留像素预渲染范围、测量缓存与原有虚拟化机制。
- 右侧工具栏宽度直接随开关状态生效，移除宽度过渡，避免动画每一帧都让聊天内容换行、重新测量。保留面板自身的透明度和位移动画。

## 桌面验证

2026-09-14 在当前项目 `target/debug/liveagent` 的真实 WKWebView 中验证，通过开发调试桥驱动滚动及采样；不是浏览器预览或安装的正式版。使用已有的开发种子入口创建“性能测试 · 1600 轮长会话”，包含 Markdown、代码及工具记录。会话 ID 为 `81cae7d7-d95e-4931-a31b-e9b48c85390f`，完整加载后有 3201 个时间线条目，没有发起真实模型请求。

- 到顶加载一页后停止输入，条目数量保持不变；重复主动向上操作可逐页加载至 3201 条。
- 全量历史下，滚动测试最多挂载 38 个虚拟行，文档节点约 1400 个，没有随历史总数全部挂载。
- 同一会话和滚动区域的 3 秒程序化滚动对比：同步提交时帧间隔 P95 为 165ms；关闭同步提交后的三次采样分别为 18、35、49ms。开发环境存在明显波动，后两次仍有超过 50ms 的帧间隔。
- 右栏开关引起的聊天视口宽度采样从 8 个不同值减少到 2 个（起始值、最终值）。这能验证重复布局减少，不能直接作为 INP 改善数值。
- 一次程序化跳转复测捕获到空白覆盖采样；后续带位置记录的复测没有重现。异步渲染在快速跳转、复杂 Markdown 下仍需关注，不能据此宣称完全无掉帧。

## 检查与复测路径

GUI、共享 UI、Gateway WebUI 类型检查通过；相关历史预取、滚动跟随、虚拟行模型和工作栏边界测试通过，修改的生产代码通过 Biome 检查。未进行生产包 INP 测量，未用真实模型流式输出做本轮桌面验收。

1. 打开测试会话，向上到达已加载边界后停住，确认只新增一页且正在阅读的内容不跳走；继续向上再加载下一页。
2. 分别使用滚轮、PageUp/Home、滚动条拖动；快速重复输入时检查是否有重复请求。加载期间切换会话，确认内容不串。
3. 在长会话中快速滚动，打开、关闭右侧工具栏，并拖动调整宽度，检查空白、换行和阅读位置。
4. 点击“回到底部”，再向上脱离跟随；后续真实流式回复时检查跟随、停止和历史阅读位置。

测试会话保留在本地开发数据中，方便继续复测；没有新增依赖或常驻测试脚本。

## 第二轮：合并行高度更新

侧栏开关采样发现，行高度变化逐个通知虚拟列表更新；调试栈中一次滚动位置读取触发的布局耗时达到 47ms。此次在本地虚拟列表实现中，将同一帧的 ResizeObserver 记录按元素合并，保留最新高度，再集中发布布局。仅在 origin 锚定且不需要末端补偿时合并通知；offset 补偿和末端钉住保留逐次发布的顺序，避免滚动写入被旧容器高度截断。观察器断开时取消待执行的测量。

新增 5 项行为测试，覆盖同步/延迟测量批次、同一节点多次上报、节点移除与取消、末端补偿顺序。三行同时变化时通知次数由 3 次降为 1 次，同时验证原阅读行坐标不变。虚拟列表共 30 项测试、GUI 历史/行模型/跟随相关 69 项测试通过；虚拟列表、GUI、Gateway WebUI 类型检查通过。通知次数减少属于确定性验证，不等同于整页 INP 已经达标。

最终桌面复测加载到 3203 条时间线记录（测试会话中已有后续记录）。3 秒滚动采样 P95 为 35ms，仍有 6 个超过 50ms 的帧间隔；程序化跳转后的首个采样存在局部覆盖空隙，后续滚动未记录到空隙。六次侧栏开关的最大帧间隔依次为 80、37、40、41、47、40ms，首次仍有慢帧。这些开发环境数据有窗口焦点和冷缓存影响，不构成严格的前后性能对照；本轮能确定的是减少了重复通知，仍未解决所有慢帧及快速跳转首帧问题。
