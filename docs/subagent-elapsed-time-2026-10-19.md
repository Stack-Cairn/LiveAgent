# 多个子 Agent 后出现异常处理时长

## 问题与原因

现象：启动多个子 Agent 后，后续回复可能出现 `已处理 497886h30m8s`。

确认的代码路径：

1. K-brain 为用户手动输入设置 `SentAt`，但部分后台续跑、共享输出和引导消息缺少时间戳。
2. LiveAgent 历史转换把缺失的 `created_at` 替换为消息序号 `index + 1`。
3. 转录界面将消息序号作为 epoch 毫秒，与真实回复时间相减，得到接近从 1970 年至今的时长。

## 修复

- K-brain 为新产生的后台消息、上下文通知和运行中引导消息设置真实时间戳；保持 `Authored` 标记语义不变。
- LiveAgent 历史转换以 `0` 表示未知时间，不再伪造时间戳。
- 桌面和 WebUI 共用耗时校验：缺失、非有限值、消息序号、秒级值及倒序时间不能生成历史耗时。
- 活动区块遇到未知起点时从本次挂载开始计时；重载缺少时间的旧记录只显示“已处理”，不猜测历史耗时。
- 保留合法的长任务耗时，没有设置任意小时数上限，也不改写旧会话。

## 验证

- 桌面前端：3,331 项通过、1 项跳过。
- WebUI：804 项通过。
- 桌面和 WebUI TypeScript 类型检查通过。
- K-brain `internal/ai`、`internal/agent`、`internal/backend`、`internal/session`、`internal/protocol` 包测试通过；后台计时回归通过 `-race` 检查，覆盖三个并行 Agent 各连续运行三轮。
- 计时回归覆盖：HTTP 历史恢复、桌面转录行、未知时间、倒序时间、合法 50 小时任务、三个活动区块独立结束和卸载重挂。
- Chrome 浏览器分别使用桌面端和 WebUI 的 Vite 环境加载真实共享组件，在 1280×900 和 390×844 视口验证三个区块运行、部分完成、全部完成、展开折叠和历史重挂。正常区块显示 13 秒，缺少时钟的运行区块在完成时显示本次观察到的 5 秒；历史重挂后未知耗时不显示数值。

浏览器验证使用受控时钟和组件测试页面；不等同于使用用户真实资料与在线模型完整运行三子 Agent。后端并行 Agent 使用本地模型响应测试服务验证。本次代码交付不包含发版。
