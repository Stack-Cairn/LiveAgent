## macOS 真实验收

隔离目录 `/private/tmp/kb-cache-acceptance/`，没有复制正式聊天或修改正式应用。使用开发桌面程序和新 KB 二进制，供应商配置中的 `gpt-6-luna`，真实外部请求，不模拟模型 usage。

1. 桌面读取随机文件；外部更新文件后再次读取，确认工具执行没有被旧结果缓存替代。
2. 在隔离后端添加官方 `@modelcontextprotocol/server-filesystem`，只允许测试目录；桌面实际调用 `mcp__cache-fs__read_text_file`。
3. Chrome 浏览器连接相同 KB，追加三轮问题；每轮在模型外更新 nonce，真实 MCP 返回对应新内容。其中模型额外调用了 `get_file_info`，计数如实保留。
4. 浏览器聊天、轨迹、页面重载后的历史与累计统计一致，未捕获页面 JavaScript 错误；系统时间标签没有出现在聊天正文。
5. 桌面重新加载页面后确认完整六轮聊天及累计 **83%**；隔离 MCP 测试后禁用。

## 验收中发现的既有不足

- 浏览器追加三轮后，已经打开过该会话的桌面页离开再进入时，聊天正文仍停留在前三轮，轨迹累计统计已是六轮；完整刷新桌面页后正文恢复。这是跨客户端历史刷新不一致，本次缓存修改未触及该前端路径，**尚未修复**。
- 97% 的持续整体命中率尚未达到。本次只证明无意义前缀变化已消除、单次可到 98%、真实工具继续返回新数据。
- 未做真实 Anthropic、DeepSeek 官方供应商调用；对应协议和缓存关闭路径通过本地测试。没有宣称所有模型都已实机验收。
