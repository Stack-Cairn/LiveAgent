# 旧对话恢复与自定义时区启动隔离验收

## 范围

- K-brain：`main`，`9fdadd75a0ef19fd855e5888d81ae0557ad7d636`。
- LiveAgent：`v2-kbrian`；sidecar source lock 已更新到上述提交。
- 本轮没有创建发布标签、替换 beta.3 附件或覆盖正式安装。

## 修复

1. 显式 `-session-dir` 同时读取平铺与项目分组的旧会话，原位读写，不复制覆盖既有记录；重复 ID 拒绝修改。
2. 前端不再直接信任已迁移缓存。先验证远端会话存在，仅在 404 时重新导入；401、403、500、网络异常不会触发重导入。
3. 打开旧对话遇到 404 或缺少映射时，按需查找 SQLite/Pi 导出源并重试一次；并发恢复合并。
4. 后端持久化删除标记，导入已删除会话返回 410，防止自动迁移复活本次修复之后删除的记录。
5. 后端连接命令不再执行旧日程迁移。日程迁移在使用日程查询/导出/修改/订阅时按需执行，失败可重试。
6. K-brain 启动不打开日程文件，不校验其中的时区；无效自定义时区仅影响日程请求，不阻断健康检查、会话列表或聊天。后台提醒轮询不会初始化日程。
7. 二进制内置 IANA 时区数据库；未删除或改写用户自定义时区，未自动替换成 UTC。

## 边界

- 本轮未声称用户真实 404 会话已全部恢复；尚未用具体失败 ID 验证源数据是否存在。
- 修复之前已删除且没有删除标记的旧会话，无法与迁移目标丢失可靠区分。
- 日程改为按需初始化，因此本次启动尚未使用日程时，提醒与订阅处理不会由空轮询启动；使用日程后恢复处理。
- 无效自定义时区仍会在日程内提示修正，不会被静默解释为另一个时区。未实现任意非 IANA 自定义时区字符串的解析。
- 已发布 beta.3 不会自动获得这些代码；需要后续新构建/发版。
