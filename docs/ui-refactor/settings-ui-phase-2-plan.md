# UI 第二阶段：设置页重构计划

> 本文是 UI 第二阶段的第一个工作包，目标是统一 LiveAgent Desktop 与 Gateway WebUI
> 设置页的视觉语言和交互行为。它属于 `docs/ui-refactor/` 下的临时执行文档，PR 合并前按
> 本目录约定删除。

## 1. 背景与范围

第一阶段已经完成大规模样式迁移、共享组件收口、动画治理和命令式 DOM 清理。第二阶段允许
有意调整视觉和交互，不再以像素级保持旧界面为首要目标。

本工作包只处理设置体验：

- 设置页外壳、导航、搜索、内容宽度和滚动边界。
- 设置卡片、设置行、表单字段、提示、空态、加载态和操作区。
- Switch、分段选择、Select、可搜索选择器、数字输入等设置控件。
- 设置弹窗、抽屉、嵌套弹层和表单的保存、取消、校验、焦点行为。
- Desktop 与 Gateway WebUI 的响应式差异。
- 设置相关动画和异步反馈。

本工作包不主动改动：

- Provider、MCP、SSH、Cron 等设置背后的协议和存储格式。
- MentionComposer、编辑器内核、聊天主界面和工作面板。
- 与设置体验无关的后端重构。

如果交互统一必须改变保存时机、默认值或持久化行为，应把它列为单独变更并增加对应测试，
不能混在纯样式提交里。

## 2. 参考应用实测结论

参考对象为本机安装的 PI-Desktop 0.14.6；源码目录 `../pi-desktop` 当前为
0.14.7-beta.1。安装版行为和源码存在小幅版本差异，以下结论以实际操作为主、源码用于解释。

### 2.1 已覆盖的交互

本轮实际操作了 11 个设置入口和 20 多种状态：

- 设置导航搜索、无结果状态和跨分区跳转。
- 主题、语言、字体、100%/125% 字号切换。
- 系统/直连/自定义代理切换、非法 URL 校验和恢复。
- AI 权限、默认模式、链接打开位置、Enter 发送和数字阈值输入。
- 快捷键录制、冲突前状态、恢复默认值。
- 全局指令编辑、未保存离开。
- 模型服务选择、定制端点、嵌套高级设置。
- Skill 编辑、启停、取消、新建模板和表单校验。
- MCP 本地/HTTP 连接方式切换、取消和辅助信息。
- 子智能体模板、工具权限和高级配置。
- 会话导入扫描、分组、展开、批量选择入口和加载状态。
- 项目空态、排序、搜索和原生文件夹选择器。
- 发版日志、检查更新和开发者模式依赖项。
- 亮色/暗色、窗口最小尺寸和弹层焦点恢复。

测试期间没有创建 Provider、Skill、MCP、子智能体或项目；临时修改的设置均已恢复。

### 2.2 值得吸收的设计原则

1. **依靠表面层级分组。** 页面、行卡片和浮层使用三档背景，普通内容卡片很少依赖描边或重阴影。
2. **保持行结构稳定。** 普通设置始终是左侧标题/说明、右侧控件；同组设置具有一致高度、内边距和对齐。
3. **按风险决定保存方式。** 主题、字号、模式和开关即时保存；长文本和复杂配置使用明确保存按钮。
4. **异步反馈留在触发位置。** 扫描和检查更新时禁用原按钮并替换文案，结果在原卡片展开，不使用阻断弹窗。
5. **复杂选择器允许搜索。** 主题、语言、字体、服务和模型使用可搜索菜单；短且稳定的枚举使用分段控件。
6. **弹层有清楚的层级。** 嵌套弹窗按最内层到最外层关闭，并把焦点恢复给对应入口。
7. **状态变化克制。** 主要反馈来自背景、文字和控件位置；简单交互约 150–200ms，不给每张卡片增加入场动画。
8. **能力管理使用统一工作台。** Scope、搜索、计数、项目选择、列表、空态和新增操作在 Skills、MCP、子智能体中保持一致。



### 2.3 不应照搬的问题

- 设置导航搜索只过滤左侧入口，不搜索或定位当前页面内的具体设置。
- 原生 `<select>` 和自建可搜索菜单混用，视觉和键盘行为不完全一致。
- 数字阈值非法时静默恢复旧值，没有说明有效范围。
- 全局指令和部分创建表单在离开或关闭时静默丢弃草稿。
- 高级区域展开后可能落到弹窗可视区以下，没有主动保持当前内容可见。
- 安装版 MCP HTTP 地址出现过与命令字段相同的辅助说明，辅助名称需要纳入回归测试。
- `NetworkProxySection` 复制了一份 `SettingsRow`，公共外观仍存在实现漂移。
- 自建 `AnchoredMenu` 有 259 行，`settings.css` 有 2,159 行。参考其行为，不复制其 CSS 和组件复杂度。
- 桌面主窗口最小宽度为 1040px，因此设置布局未真正进入手机级窄屏。Gateway WebUI 不能依赖这个假设。



## 3. LiveAgent 当前基线

当前设置相关目录包括 37 个 TSX 文件、约 19,756 行代码。`SettingsShell` 已提供分组导航、
搜索、保存状态和 Desktop/Web 双宿主布局；设置展示层已有 7 个共享组件。

已有基础可以继续使用：

- `SettingsShell`
- `SettingsSurface`
- `SettingsPanel` / `SettingsHint`
- `FormField`
- `ChoiceCard`
- `SettingsNotice`
- `SettingsCopyButton`
- `StepMarker`

当前主要问题：

- `SettingsSurface` 默认同时使用边框和阴影，多个业务页面又追加各自的边框、背景和 hover 状态。
- 设置范围内约有 246 处边框、阴影、任意圆角、`transition-all` 或局部动画时长写法，需要逐项归并。
- `SettingsShell` 的 Web 响应式规则集中在一个很长的 class 常量中，页面语义和断点行为难以阅读。
- 现有展示组件以结构收口为主，还没有形成完整的设置行、工具栏、分组列表和异步状态契约。
- Provider、Cron、Hooks 等复杂页面已经部分使用共享组件，但不同页面的密度、操作区、校验和弹窗行为仍然不同。

第一批改动已建立设置页基础视觉：

- 新增共享 `SettingsSection`、`SettingsCard` 和 `SettingsRow`，System、提示词模板、语音输入、系统工具、Computer Use、定时任务、SSH 和 Remote 已开始使用统一结构或表面。
- 设置导航宽度收敛到 272px，并统一返回入口、搜索框、分组和选中态。
- 新增 Rail、Tile、Tile Hover、Active 四个设置语义色，浅色使用中性灰，避免继承通用 `muted` 的蓝色倾向。
- 普通设置行采用 14px × 16px 内边距、6px 组间距、无默认边框和阴影。
- 系统设置的执行模式、主题和桌面关闭行为已从并列选择卡收成统一的单行选择器；无说明的设置行不再被固定最小高度撑大。
- Installed Skills 已从响应式卡片墙改为单列资源清单；Provider 与 MCP 的管理行统一为中性 Tile，MCP 删除列表外框和行分割线。
- Hooks 删除重复页内标题、三张外层描边卡和四套生命周期装饰色，保留生命周期导航与当前事件两层；空态改为可直接操作的紧凑行。

- 已通过开发版桌面进程和窗口 ID 逐页检查 System、供应商、提示词模板、Skills、MCP、定时任务、记忆、Hooks、系统工具、Computer Use、语音输入、SSH、Remote、快捷键、备份与同步和关于；同时验证 Gateway WebUI 浅色、深色、640px 和 520px 布局。
- 以本工作包覆盖的 62 个 TSX 文件为统计口径，相对 `HEAD`：`border` 类引用从 786 降至 569（减少 217），`shadow` 从 135 降至 104（减少 31），`transition-all` 从 29 降至 0，任意圆角从 1 降至 0。
- Computer Use 状态卡已删除两层装饰光晕、渐变背景和状态投影，时间轴过渡统一为 150ms。
- 定时任务和 SSH 删除重复的彩色页内标题栏；Remote 的连接、认证、高级选项和状态改为无描边中性分组；快捷键行改为中性填充层级。
- 关于页从双栏仪表盘收成应用、软件更新和预发布通道三行；发布说明移入弹窗，更新操作固定为两列且由 toast 承载检查、安装和失败状态，默认页面只保留稳定说明文案。
- 新增共享 `SettingsToggleGroup`，已覆盖字体大小 3 行，以及浏览器自动化模式、Computer Use 超时预设、SSH 视图、供应商流式重试、提示缓存保留期和备份服务预设 6 处选择；删除 SSH 视图切换的自建滑块动画。
- 新增共享 `SettingsCombobox`，系统设置中的界面、聊天和代码字体 3 个长列表选择器已支持搜索、键盘导航、空结果提示和弹层焦点，仍保留系统默认、自定义字体及本机字体路径。
- Select、Combobox 和 Toggle Group 统一使用 Active/Tile Hover 表面、150ms 状态变化、键盘焦点 ring 与浮层层级；Toggle Group 选中项增加稳定的背景、描边和阴影对比。
- 设置范围内的剩余 `aria-pressed` 已完成语义审计：语音服务、记忆条目和整理历史表达当前条目；快捷键录制表达瞬时录制状态；Provider 顶部 `fieldset` 是动作组，均不应替换成单选分段控件。
- 修复 STT 设置在持久化 provider 为空时关闭配置弹窗会把 `null` 传给选择回调的类型与运行时边界，回退到当前有效 provider。



## 4. 目标视觉系统



### 4.1 表面层级

设置页只保留以下主要层级：


| 层级       | 用途                         | 默认表现                       |
| -------- | -------------------------- | -------------------------- |
| Page     | 页面和内容画布                    | 最低层背景，不加装饰                 |
| Rail     | 设置导航                       | 与 Page 有稳定明度差，不依赖明显分割线     |
| Row/Card | 设置项、分组列表                   | 轻微抬升背景，默认无阴影，必要时用低对比边框     |
| Floating | Dialog、Popover、Select、Menu | 可使用边框和一档共享阴影               |
| Critical | 错误、危险确认                    | 使用 destructive 语义色，不另造业务红色 |


普通设置卡片不应同时叠加明显背景、边框、ring 和 shadow。键盘焦点 ring 不计入装饰层级。

### 4.2 尺寸和排版

- Desktop 设置导航以 256–276px 为目标区间，最终选择应与应用侧栏和窗口最小宽度一起验证。
- 普通内容列设置统一最大宽度，长列表型页面允许使用更宽或填充模式。
- 页面标题、区块标题、设置标题、说明文字形成四档稳定层级。
- 普通行默认采用两列结构；空间不足时整行切为上下结构，不能只压缩说明文字。
- 胶囊、头像和圆点使用 `rounded-full`；普通控件使用 Tailwind 标准圆角档位。
- 能由 Tailwind 表达的样式全部写在组件中，按 `cn(...)` 分为布局、视觉、状态和响应式组。
- CSS 仅保留主题变量、基础定义、必要关键帧、第三方节点和无法合理挂到 React 节点的规则。



## 5. 公共组件目标



### 5.1 SettingsSection

统一页面内区块标题、说明、右侧操作和内容间距。

需要支持：

- 标题和可选说明。
- 单个或多个区块操作。
- 普通、紧凑、填充三种内容模式。
- 移动端操作区换行。



### 5.2 SettingsCard

统一一组设置项或一个配置块的表面。

需要支持：

- 默认行组。
- 可折叠配置。
- 独立表单。
- 空态和加载态。
- 默认不允许调用方重复添加阴影和圆角。



### 5.3 SettingsRow

统一标题、说明、状态和右侧控件布局，替代业务页面中的相似行。

需要支持：

- 普通控件行。
- 可点击 Action Row。
- 错误或帮助文本。
- pending、disabled 和只读状态。
- 桌面双列与窄屏上下布局。
- 标题、说明和控件之间完整的 ARIA 关联。



### 5.4 SettingsToolbar / SettingsCollection

统一 Skills、MCP、Hooks、Cron、Provider 等管理页面的：

- Scope 或分类分段按钮。
- 搜索框和清除操作。
- 项目/服务筛选器。
- 数量 Badge。
- 新增、刷新、导入等主要操作。
- 分组标题、列表行、空态、加载态和错误态。



### 5.5 SettingsDialogForm

在现有 Dialog/Sheet 上统一设置表单行为：

- 打开后聚焦第一个可编辑字段或弹窗标题。
- Escape 只关闭最内层弹层。
- 关闭后焦点返回触发入口。
- 保存中禁止重复提交和意外关闭。
- 有未保存草稿时，根据内容成本决定确认、保留或明确丢弃。
- 错误出现在相关字段附近，同时提供 `role=status` 或 `aria-describedby`。
- 展开高级设置时保证展开标题或首个字段仍在可视区域内。



## 6. 保存与反馈契约

按设置类型采用一致策略：


| 设置类型           | 保存策略            | 失败反馈                |
| -------------- | --------------- | ------------------- |
| Switch、主题、枚举模式 | 乐观即时保存          | 回滚控件并显示 Toast/行内错误  |
| 数字、URL、路径      | 失焦或 Enter 校验后保存 | 保留输入并显示范围/格式错误      |
| 长文本            | 显式保存            | 保留草稿并显示卡片内错误        |
| 多字段配置          | 弹窗统一提交          | 保留弹窗、定位首个错误字段       |
| 删除和不可逆操作       | 明确确认            | 保留对象并显示错误           |
| 扫描、刷新、连接测试     | 原位异步状态          | 原卡片显示结果，必要时辅以 Toast |


所有保存状态必须使用同一组术语：未修改、保存中、已保存、保存失败。短时间成功反馈不应持续闪烁，
也不应让整个设置页频繁重排。

## 7. 动画策略

Motion 用于需要挂载生命周期或布局插值的交互：

- Dialog、Sheet、Popover 和可搜索选择器的进入/退出。
- 高级设置、条件表单和异步结果块的展开/收起。
- 管理列表中的插入、删除和排序。
- 跨分区内容切换中确有必要的轻量过渡。

Tailwind transition 用于：

- 颜色、背景、边框和透明度。
- Switch knob、按钮按压和焦点 ring。
- 不依赖卸载等待的简单状态变化。

约束：

- 禁止 `transition-all`，明确列出实际变化属性。
- 普通状态以 150–200ms 为主；大浮层不超过约 250ms。
- 不给所有设置行添加逐项入场或波浪动画。
- Motion 与 CSS 都必须遵循 reduced motion。
- 同一种浮层只允许一个动画所有者，避免 Dialog 和内部内容重复缩放。



## 8. 实施顺序



### Wave 1：外壳和基础视觉

- 整理 `SettingsShell` 的布局、Rail、内容宽度、标题、滚动和保存状态。
- 把超长响应式 class 按区域拆成可读的 `cn(...)` 分组或小组件。
- 建立 Page/Rail/Row/Floating 表面层级。
- 同时验证 Desktop 和 Gateway WebUI，不依赖 PI 的 1040px 最小窗口策略。

完成标志：所有设置分区切换时外壳不跳动，滚动容器唯一且明确，亮暗主题层级一致。

### Wave 2：SettingsSection / Card / Row

- 扩展现有设置展示层，不再新增页面私有的同构卡片和行。
- 先迁移 System、Agents、STT 这些普通表单页。
- 收敛卡片边框、阴影、圆角、行高、说明文本和操作区。

完成标志：普通设置页不再各自定义同义结构；调用方只保留业务布局差异。

### Wave 3：输入和选择控件

- 统一即时保存、失焦保存和显式保存三种流程。
- 统一数字范围、URL、路径和必填字段的行内校验。
- 明确何时使用 Select、可搜索 Combobox 和分段按钮。
- 复查 Switch、Checkbox、RadioGroup 的标签和键盘语义。

完成标志：同一种数据类型在不同页面具有相同的编辑、提交和错误行为。

### Wave 4：能力管理工作台

- 统一 Skills、MCP、Hooks、Cron、Provider 的工具栏、计数、搜索、Scope、列表和空态。
- 统一行内操作、更多菜单、启停反馈和二次删除确认。
- 优先复用现有共享组件，避免复制 PI 的大型自建菜单。

完成标志：用户在任一能力页面学会的搜索、筛选、新增和管理方式可以迁移到其他页面。

### Wave 5：弹窗和复杂表单

- 统一 Provider、Hook、Cron、Agent 模板、Memory 等复杂弹窗。
- 处理嵌套弹层、内部滚动、sticky actions、首错定位和未保存草稿。
- 引入必要的 Motion 生命周期动画。

完成标志：所有设置弹窗都通过相同的焦点、Escape、取消、保存和错误矩阵。

### Wave 6：删除漂移并收尾

- 删除迁移后无消费者的设置样式、局部组件和重复常量。
- 扫描剩余 border、shadow、任意圆角、`transition-all` 和页面私有 Switch/Row/Card。
- 更新 PR 量化数据和复线测试记录。



## 9. 复线测试矩阵



### 9.1 全局路径

- 从聊天页进入设置，再返回原页面；返回后焦点和滚动位置合理。
- 逐个打开所有设置分区，确认标题、内容宽度和滚动容器不跳变。
- 搜索命中单项、多个分区和无结果；清空后恢复完整导航。
- 在保存中、保存成功和保存失败状态切换页面。
- 刷新或重启后确认即时保存与显式保存的数据均正确恢复。



### 9.2 主题和尺寸

- Desktop：亮色、暗色、系统主题。
- Desktop：最小窗口、常用窗口、最大化。
- Gateway：大屏、820px、640px、520px 和触屏输入。

### 9.3 键盘和焦点

- Tab/Shift+Tab 可以顺序遍历导航、表单和操作区。
- Enter/Space 正确操作按钮、Switch、Radio 和菜单项。
- 可搜索选择器支持输入、上下键、Enter、Escape 和清空。
- 弹窗打开时焦点被限制在弹窗内，关闭后回到入口。
- 嵌套弹层按层关闭，不会一次退出整个设置表单。
- `focus-visible` 只在键盘路径出现，鼠标点击不叠加额外装饰边框。



### 9.4 保存、校验和取消

- 即时保存失败后回滚到后端真实值。
- 数字越界、非法 URL、空必填项、重复名称和路径不存在均有明确提示。
- 保存中不能重复提交；失败后用户输入不丢失。
- 取消未修改表单直接关闭；有价值的草稿按约定确认或保留。
- 切换设置分区不会无提示丢失长文本草稿。



### 9.5 动画

- 正常模式下检查弹窗、菜单、条件表单和列表变化的方向与节奏。
- 连续快速打开/关闭不会闪现底层页面或遗留不可点击遮罩。
- reduced motion 下不播放位移、缩放和布局弹簧，只保留必要的即时状态反馈。
- 动画结束前后 DOM、焦点和可点击区域保持一致。



## 10. 量化与完成标准
